# 内核性能优化记录

日期：2026-10-15。比较基线：`e90ec73`。本轮处理原始报告中的 O02 和 O05，C ABI 保持 7。

## 已完成的改动

- 编码任务创建一次工作线程，映射和 LZW 阶段共享，结束时统一回收；单线程及单个有效任务直接执行。任务队列和在途帧数受批次限制，结果按源帧顺序写出。
- 复用批次的 RGB、索引、压缩块，以及每个 worker 的六行 Floyd 误差、LZW 字典和位流缓冲。每帧重置误差与字典；有损预处理直接修改已读取的 RGB，下一批读取会覆盖它。
- 原始帧读取复用已有长度的缓冲，避免先清零整帧再立即读取覆盖。待写帧与当前帧交换压缩缓冲的所有权。
- 映射后先按实际显示画布判断重复和延时容量，可合并的帧直接跳过 LZW。跨批次、跨采样段与最大 65535 cs 延时拆分沿用同一套规则。
- 透明差分在同一次画布比较中计算最小变化矩形，只压缩矩形内的行，无需另外复制紧密排列的矩形像素。首帧与各采样段的关键帧仍覆盖完整画布。
- 不合并的无变化帧写成 1×1 透明帧以承载延时；矩形使用 DoNotDispose。相同索引直接判为不变，避免无用的调色板颜色查询。
- worker 出错时收齐本批结果再返回，取消或输出失败后关闭队列并等待线程退出；线程创建失败返回明确错误。

## 实测结果

Windows、Rust 1.99.0 GNU、release、同一台机器。四组合成素材均固定调色板、30 fps、无抖动；每个配置运行三次，记录中位数。计时覆盖 raw 文件读取、映射、差分、LZW 和计数字节的输出，**不含 FFmpeg 解码、调色板生成或真实 GIF 落盘**；因此这些数字不能作为整个转换过程的加速比例。前后生成素材与测试代码一致，基线仅增加相同的基准入口。

| 素材 | 线程 | 优化前 ms | 优化后 ms | 耗时减少 |
| --- | ---: | ---: | ---: | ---: |
| 48×48，600 帧变化画面 | 1 | 47.918 | 34.031 | 29.0% |
| 同上 | 4 | 56.310 | 19.575 | 65.2% |
| 640×360，120 帧静止，透明优化及去重开启 | 1 | 769.437 | 535.992 | 30.3% |
| 同上 | 4 | 300.153 | 187.524 | 37.5% |
| 640×360，120 帧移动 24×24 方块，仅透明优化开启 | 1 | 759.860 | 529.112 | 30.4% |
| 同上 | 4 | 303.805 | 178.004 | 41.4% |
| 640×360，120 帧全画面运动，关闭透明优化及去重 | 1 | 645.054 | 639.563 | 0.9% |
| 同上 | 4 | 231.275 | 212.203 | 8.2% |

局部运动样本从 **116231 字节降到 15292 字节，减少 86.8%**。其余三组样本的文件大小保持一致。所有数字只代表这些合成负载；全画面运动的单线程结果接近原水平，不能据此宣称普遍大幅提速。本轮未测量进程峰值 RAM；缓冲池会保留容量直到任务结束，批次预算仍不是严格的进程内存上限。

可重复执行基准：

```powershell
cargo test --release --offline --lib encoding_workload_benchmark -- --ignored --nocapture
```

## 正确性与兼容性验证

- `cargo test --offline` 与 `cargo test --release --offline`：62 个单元测试、15 个新回归集成测试、13 个原有集成测试，共 90 项；普通运行忽略两个手动基准，本轮另外单独运行并通过编码基准。
- 独立 GIF LZW 读取器验证复用字典的不同码宽、字典清空和错误恢复；矩形测试验证行跨度、偏移和越界拒绝。
- 持久 worker 在 None/Bayer/Floyd 下反复处理同一批素材，验证误差行清零和多线程一致性；模拟压缩错误后继续使用队列，验证没有遗留结果。
- FFmpeg 回读验证局部变化触及四边、静止帧、去重开关、透明像素与两次真实循环播放；按延时展开后与完整帧输出逐像素一致。短片估算与实际矩形输出字节数一致。
- 7000 秒静止时间线在透明优化开关及 1/4 线程下均拆成 11 帧，总延时保持 700000 cs。
- 使用本轮之前的 release 内核与新内核分别导出同一视频，关闭透明优化时，None、Bayer、Floyd 加有损处理的三组 GIF 的 SHA256 完全一致。开启透明优化时描述符和压缩字节允许改变，显示结果和时间语义保持一致。

`cmake --build --preset mingw-release` 完成桌面程序重建。实际启动最终程序并通过 C++/QML 桥接导出成功，退出码 0；FFprobe 回读为 GIF、320×240、60 帧、5.000 秒。修改的 Rust 文件通过 rustfmt 检查，补丁通过 `git diff --check`。已有 MinGW 链接警告与 QML 绑定提示仍存在。
